# oh-my-maek v1

localhost에서 실행하는 개인 노트 앱. 평면 노트 목록과 Markdown 에디터, 노트를 행으로 다루는 데이터베이스를 제공합니다.

## 실행

Node.js 22.12+ 또는 24+가 필요합니다.

```sh
npm install
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)을 엽니다. 폴더 연결이나 계정 설정 없이 새 노트를 만들 수 있습니다.
서버는 `127.0.0.1`에만 바인딩합니다. 종료는 터미널에서 `Ctrl+C`입니다.

```sh
PORT=3001 npm run dev
MAEK_DATA_DIR=/absolute/path/to/app-data npm run dev
```

`MAEK_DATA_DIR`은 서버 관리용 저장 위치 설정이며, 앱에서 기존 폴더를 연결하는 기능은 없습니다.
의존성 설치 후 앱 실행·편집·미리보기는 인터넷 연결 없이 가능합니다. 노트에 직접 넣은 외부 이미지·링크는 예외입니다.

## 포함한 기능

- 노트 생성, 제목 변경, 복제, 자동 저장(입력 후 700ms), 수동 저장
- 제목·본문·태그 검색, 이름순·최근 수정순 정렬, 태그 필터, 즐겨찾기
- Markdown 편집과 읽기 보기: 제목, 굵게, 기울임, 목록, 체크리스트, 인용, 코드, 표, 링크, 이미지 문법, 수식
- 노트 연결과 백링크, 단어·글자 수, 읽기 시간, 집중 모드
- 오늘의 노트·회의·아이디어 템플릿, 기존 노트를 사용자 템플릿으로 지정
- 휴지통과 복원, 최근 30개 저장 버전의 제목·본문·태그 복원
- 여러 Markdown 파일 가져오기, 개별 Markdown 내보내기, 전체 데이터 JSON 내보내기
- 데이터베이스 생성, 노트를 행으로 추가·연결, 표·칸반 보기, 검색·상태 필터·정렬, CSV 내보내기
- 사용자 속성: 텍스트, 숫자, 날짜, 체크박스, 선택. 칸반은 기본 상태 `할 일 / 진행 중 / 완료`로 구성
- 라이트·다크 모드, 작은 화면에서 전체 너비 에디터

폴더 트리, 로컬 폴더 연결, Tiptap, 우측 패널, AI 채팅, STT·녹음 기능은 실행 경로에 없습니다.

## 데이터와 복구

```text
.maek-data/                    # Git에서 제외
  notes/<uuid>.md             # YAML 속성 + Markdown 본문, 원본 데이터
  databases.json              # 데이터베이스 이름과 속성 정의
  history/<uuid>/<hash>.md    # 노트별 최근 30개 이전 버전
```

Markdown 파일이 원본입니다. 데이터베이스도 YAML에 기록된 `databaseId`, `status`, `properties`를 화면에서 모아 보여주는 방식이며 SQLite는 사용하지 않습니다. 외부 프로그램은 파일 본문을 수정할 수 있으며, YAML의 식별자·시간·속성 형식은 유지해야 합니다. 새 노트 생성은 앱 또는 API를 이용하세요.

저장은 기존 내용 해시를 검사하고, 이전 버전을 남긴 다음 임시 파일을 rename합니다. 다른 창이나 프로그램이 바꾼 파일은 `409`로 저장을 거부합니다. 창에 포커스를 다시 주면 디스크 내용을 새로 읽으며, 저장하지 않은 편집본은 보존합니다. 저장 실패 시 배너에서 편집본을 다운로드하거나 **편집본 보관 후 새로고침**으로 최신 파일을 불러올 수 있습니다. 브라우저 임시 저장본은 새로고침 후 복구됩니다.

전체 복구 가능한 백업은 서버를 종료한 뒤 `.maek-data/` 폴더 전체를 복사해 보관하는 방법입니다. 복구 시 서버를 종료하고 보관한 폴더를 `MAEK_DATA_DIR`로 지정하세요. UI의 JSON 내보내기는 데이터 이식용이며, v1에는 JSON 복원 UI가 없습니다.

## 개발·검증

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium  # 브라우저 테스트 최초 1회
npm run test:e2e
```

브라우저 테스트는 3100번 포트와 OS 임시 폴더를 사용해 실제 노트를 건드리지 않습니다.
`npm run build`는 클라이언트 번들 검증용입니다. API를 포함한 실행 명령은 `npm run dev`입니다.

```text
client/src/notes/     v1 UI, 편집 상태, Markdown 렌더링, 데이터베이스
server/app.ts        검증된 노트·데이터베이스 HTTP API
server/library.ts    파일 저장, 충돌 검사, 버전 관리
shared/notes.ts      노트·데이터베이스·속성 스키마
shared/frontmatter.ts 기존 Markdown frontmatter 유틸리티
tests/               저장소·API·기존 파일 유틸리티·브라우저 테스트
legacy/              작업 전 미커밋 클라이언트의 보존본 (실행·번들 제외)
```

기존 프로토타입 설명과 TODO는 [docs/prototype-v0.md](docs/prototype-v0.md), [docs/prototype-todos.md](docs/prototype-todos.md)에 보존했습니다. 이전 `server/fs/` 유틸리티와 테스트도 남아 있지만 v1 API에 연결되어 있지 않습니다.

## v1의 범위와 한계

- 개인용 단일 서버를 전제로 합니다. 동일 저장 위치에 서버를 여러 개 실행하지 마세요. 외부 프로세스와 파일 검사·교체 사이의 매우 짧은 경합까지 잠그지는 않습니다.
- 데이터베이스 속성 추가를 지원하지만 속성 삭제·이름 변경, 관계·롤업·수식, 캘린더·타임라인은 포함하지 않았습니다.
- 원문 편집기이며 WYSIWYG 블록 편집기는 아닙니다. 이미지 업로드, 코드 구문 색상, PDF·DOCX·HTML 뷰어는 없습니다. 원시 HTML을 실행하지 않습니다.
- 노트 목록은 메모리에서 검색합니다. 대규모 자료실용 색인·페이지 나누기와 실시간 파일 감시는 없습니다.
- 휴지통의 영구 삭제 UI는 없습니다. 노트는 복원 가능한 상태로 보관합니다.
- 저장 실패한 임시 편집본은 같은 브라우저·접속 주소에서 복구됩니다. 브라우저 저장소 삭제나 비공개 세션 종료에 대비하려면 편집본을 다운로드하세요.
- Markdown 가져오기는 임의 frontmatter를 버리지 않도록 알 수 없는 속성이 있으면 원문 전체를 본문에 보존합니다. 데이터베이스 관계를 자동으로 이식하지 않습니다.

렌더링 구성은 [react-markdown 공식 문서](https://github.com/remarkjs/react-markdown)와 [remark-gfm 공식 문서](https://github.com/remarkjs/remark-gfm)를 따릅니다.
