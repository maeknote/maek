# oh-my-maek

로컬 폴더의 마크다운을 소스 오브 트루스로 쓰는, 로컬 호스팅 노트 도구.

```
git clone → npm install → npm run dev → http://127.0.0.1:3000
```

배포하지 않는다. `npm run dev`가 유일한 실행 경로다.

---

## 원칙

**파일이 진실이고, 나머지는 파생물이다.**

폴더 하나가 데이터베이스 하나고, `.md` 파일 하나가 행 하나고, YAML frontmatter의 키가
컬럼이다. 나중에 붙을 SQLite 인덱스는 캐시일 뿐이라 지우고 다시 만들어도 아무것도 잃지
않는다. 외부 에디터로 `.md`를 고쳐도 그대로 반영된다.

이 원칙이 코드에서 실제로 강제되는 지점은 세 곳이다:

| 지점 | 무엇을 지키나 |
|---|---|
| `server/fs/writeFile.ts` | 저장 전 mtime + 해시 검사. 밑에서 바뀌었으면 덮어쓰지 않고 409 |
| `client/src/views/MarkdownEditorView.tsx` | 안 고쳤으면 파일에 쓰지 않는다 (Tiptap 정규화 억제) |
| `server/fs/guard.ts` | 모든 경로가 워크스페이스 안에 있음을 realpath로 증명 |

## 구조

```
server/     Fastify — API + Vite 미들웨어 (프로세스 하나, 명령 하나)
  fs/       pickDirectory · listDir · readFile · writeFile · createFile · guard
client/     Vite SPA — 셸: 탐색기 · 탭 · 뷰
  views/    탭에 꽂히는 뷰. 지금은 MarkdownEditorView 하나
shared/     contract.ts (zod RPC 계약) · frontmatter.ts (파싱 단일 구현)
```

모든 fs API는 절대 경로가 아니라 `{ wsId, 워크스페이스 기준 상대경로 }`를 받는다.
절대 경로는 `pickDirectory` / `openWorkspace`가 돌려주는 `root`에만 존재하고 서버
메모리에 보관된다.

## 알려진 한계

### TOCTOU — 검사와 쓰기 사이의 창 (수용함)

저장 경로는 `stat → hash → write` 순서로 동작한다. **검사와 쓰기 사이에 틈이 있다.**
그 밀리초 안에 외부 프로세스가 파일을 바꾸면 우리는 그 변경을 덮어쓰고, **아무 말도
하지 않는다.**

```
       stat        hash        write
─────────┬───────────┬───────────┬────────►
         │           │     ▲     │
         └─── 검사 ──┘     │     └── 여기서 덮어씀
                           │
                  외부 변경이 이 구간에 들어오면 놓친다
```

- **테스트 없음** — 재현하려면 경합을 인위적으로 만들어야 한다
- **에러 처리 없음** — 감지할 방법이 없다
- **사용자에게 무음** — 이게 이 한계에서 제일 나쁜 부분이다

**수용하는 이유:** 사용자 1명, 로컬, 단일 프로세스 조건에서 이 창은 밀리초 단위다.
완전히 닫으려면 파일 잠금이나 원자적 교체(temp 파일 + rename)가 필요하고, 그건 이
마일스톤의 범위를 넘는다. 다만 **무음이라는 점은 기록해둔다** — 나중에 이 도구를
여러 프로세스가 같이 쓰게 되면 이 결정부터 다시 봐야 한다.

이 한계는 1A/5B의 mtime+해시 검사를 **무의미하게 만들지 않는다.** 그 검사가 잡는 것은
"내가 파일을 연 뒤 저장하기 전까지의 외부 변경"이고, 그건 실제로 흔하다(다른 에디터,
동기화 폴더). TOCTOU가 남기는 것은 그보다 훨씬 좁은 창이다.

### 보안층 없음 (의도적)

로컬 서버 보안층을 만들지 않기로 명시적으로 결정했다.

- 파일을 읽고 쓰는 모든 엔드포인트가 HTTP로 열려 있다. 인증이 없으므로 이 기계에서
  도는 무엇이든 호출할 수 있고, 폴더 선택기는 홈 디렉터리 전체에 접근한다.
- `127.0.0.1` 바인딩은 DNS 리바인딩을 막지 못한다. 브라우저가 요청을 대신 보내준다.
- 되돌리는 비용은 낮다: `Host` 헤더 allowlist 미들웨어 한 장이면 된다. 다만 그때는
  모든 엔드포인트를 다시 봐야 한다.

`server/fs/guard.ts`의 realpath 경로 검사는 이 결정과 **독립적이다.** 그건 보안이
아니라 데이터 무결성이다 — 경로 조립 버그나 심볼릭 링크 하나가 노트 폴더 밖을
덮어쓰는 걸 막는다.

### Tiptap이 마크다운을 정규화한다

Tiptap을 쓰는 한 저장 시 서식 정규화(들여쓰기·공백·표 모양·순수 HTML·Obsidian 문법)는
없앨 수 없다. 대신 **누적 변형을 막는다**: 안 고치고 저장하면 파일에 쓰지 않는다
(`저장됨`이 아니라 `변경 없음`이 뜬다). "열기만 하고 안 고치면 파일이 안 바뀐다"는
보장된다.

### 그 밖에

- 파일 변경 감시(워처) 없음 — 외부 변경은 저장 시점에 409로만 드러난다
- `<600px` 미지원. 마우스·키보드 데스크톱 브라우저 전용
- 32MB 초과 파일은 읽지 않고 `unsupported`로 처리한다
