## 기존 노트 폴더 호환성 테스트

**What**
실제 사용 중인 노트 폴더의 복사본을 fixture로 삼아, 앱이 그 폴더를 열고 저장했을 때
파일이 변형되지 않는지 검증하는 테스트 세트.

**Why**
기능 목록을 다 채우는 건 성공 기준이 아니다. 기능은 표면적 분류일 뿐이고, 실제로 가진
노트가 이 앱에서 안 깨지는지는 별개 문제다. 특히 T5(Tiptap 쓰기 억제)가 제대로 도는지는
**진짜 파일로만 알 수 있다** — 합성 샘플은 Tiptap이 정규화할 거리(중첩 목록, 순수 HTML,
표 정렬, Obsidian 문법, 비표준 공백)가 없어서 항상 통과한다.

**Pros**
- 잡는 범위가 넓다. 에디터·frontmatter·경로 처리·인코딩을 한 번에 훑는다
- 만드는 비용이 낮다. 폴더 복사본을 fixture로 붙이고 순회하면 된다
- 회귀 방지 효과가 크다. 에디터 확장을 추가할 때마다 다시 돌리면 된다

**Cons**
- fixture가 개인 노트라 저장소에 넣기 곤란할 수 있다 (별도 경로 참조나 익명화 필요)
- 실패했을 때 "어느 확장이 범인인지" 좁히는 데 추가 작업이 필요하다

**검증 형태**
```
fixture 폴더의 모든 .md에 대해:
  1. 서버 readFile
  2. Tiptap에 로드
  3. 아무것도 수정하지 않음
  4. 저장 경로 실행
  → 파일 바이트가 그대로인가? (T5 쓰기 억제가 동작하는가)

추가:
  frontmatter 무수정 라운드트립 → 바이트 동일 (T4)
  파일별 viewKind 판정이 합리적인가 (T6)
```
