# Maek 웹 네이티브 UI/UX 개선 태스크 청크

## 문서 목적

Maek 웹 버전은 macOS 앱의 기능을 브라우저로 옮겼다. 실제 폴더와 Markdown 파일을 유지하고 자동 저장, 외부 변경 감지, 칸반, 미리보기를 제공한다. 앞으로의 초점은 기능을 더 쌓는 것이 아니라 브라우저의 주소, 방문 기록, 링크, 여러 탭이라는 사용 모델에 기존 기능을 연결하는 것이다.

이 문서는 분석과 실행 계획을 분리하지 않는다. 모든 청크에는 문제의 이유, 제품 판단, 구현 범위, 완료 조건, 위험을 함께 둔다. 이미 완료된 저장 점, `폴더에서 보기`, 폴더 아이콘 호환 작업은 제외한다.

## 공통 제품 원칙

> Maek 웹은 데스크톱 앱의 창을 복제한 화면이 아니라, 로컬 폴더를 탐색하고 문서를 읽고 쓰며 같은 자료를 목록·보드·미리보기로 다루는 웹 워크스페이스다.

- 폴더 트리는 로컬 파일 기반 제품의 중심 탐색이다.
- Maek 내부 탭은 같은 작업 맥락의 빠른 전환과 미저장 상태 확인을 돕는다.
- 브라우저 탭은 독립 작업, 문서 비교, 다른 맥락 보존에 사용한다.
- 브라우저 탭 바가 이미 높이를 차지하므로 고정 헤더, breadcrumb, 정상 저장 메시지를 다시 쌓지 않는다.
- 정상 상태는 조용하게 두고 충돌·연결 오류처럼 조치가 필요한 상태만 지속 표시한다.
- 새 데이터 모델을 만들기 전에 frontmatter, 칸반, 탐색기, 미리보기처럼 이미 있는 기능을 연결한다.

## TC-01. 웹 라우팅 기반: 워크스페이스·문서·폴더 URL

**상태:** 다음

현재 `wsId`는 서버 프로세스 안에서만 유효하고 문서 전환은 `openFile`, `setActiveTab` 같은 내부 상태로 처리된다. 로컬 절대 경로를 URL에 넣으면 사용자 이름과 폴더 구조가 방문 기록, 로그, 스크린샷에 노출된다.

### 제품 결정

URL에는 실제 경로와 임시 `wsId`를 넣지 않는다. 사용자가 승인한 워크스페이스를 가리키는 안정적인 `workspaceKey`와 워크스페이스 기준 상대 경로를 사용한다.

```text
/w/:workspaceKey/home
/w/:workspaceKey/note/:encodedRelativePath
/w/:workspaceKey/folder/:encodedRelativePath?view=list
/w/:workspaceKey/folder/:encodedRelativePath?view=board
```

예를 들어 `/Users/yoonchul/Documents/Project A`의 `projects/plan.md`는 다음처럼 표현한다.

```text
/w/7f3a2c/note/projects%2Fplan.md
```

`7f3a2c`는 로컬 저장소에만 실제 경로와 연결된 별칭이다. URL만으로 승인되지 않은 폴더를 열 수 있어서는 안 된다.

### 사용자 흐름

1. 사용자가 워크스페이스를 처음 연다.
2. Maek이 `workspaceKey`를 만들고 현재 홈·문서·폴더 화면에 URL을 부여한다.
3. 사용자가 주소를 복사하거나 새로고침한다.
4. Maek은 키로 승인된 폴더를 재등록하고, 상대 경로의 문서 또는 폴더를 연다.
5. 폴더가 이동되었거나 권한이 없어지면 재선택 안내를 보여준다.

### 구현 범위

- `TC-01.1` `workspaceKey`의 생성, 영속화, 유효성 검증
- `TC-01.2` 홈·문서·폴더 라우트와 단일 URL 동기화 지점
- `TC-01.3` 상대 경로 인코딩·디코딩 규칙
- `TC-01.4` 직접 URL 진입, 새로고침, 서버 재시작 후 재등록
- `TC-01.5` 문서명·워크스페이스명과 `document.title` 동기화
- `TC-01.6` 삭제·이동·지원하지 않는 파일의 복구 화면
- `TC-01.7` URL·오류·로그의 절대 경로 노출 점검

### 완료 조건

- 홈, 문서, 폴더 각각을 주소로 직접 연다.
- 문서를 바꾸면 URL과 브라우저 탭 제목이 함께 바뀐다.
- 새로고침과 서버 재시작 뒤에도 같은 워크스페이스와 문서로 돌아온다.
- 한글, 공백, `#`, `%`, 깊은 경로가 있는 파일을 안전하게 연다.
- 경로가 없거나 권한이 사라진 경우 사용자가 다시 연결하거나 홈으로 돌아갈 수 있다.

### 위험과 검증

- 직접 URL 상태와 `.maek/tabs.json` 복원이 충돌하면 직접 URL이 우선한다.
- 잘못된 인코딩이나 `..`가 워크스페이스 밖 접근으로 이어지지 않아야 한다.
- 폴더 이름 변경을 동일 워크스페이스로 복원할지, 재연결로 처리할지 규칙을 정한다.

### 관련 구현

- `client/src/App.tsx`
- `client/src/store.ts`
- `client/src/host.ts`
- `server/workspaces.ts`
- `server/host.ts`

## TC-04. 발견 가능한 폴더 목록·보드 보기

**상태:** 다음

### 분석 이유

현재 칸반은 폴더 우클릭의 `Open as Kanban`을 알아야 쓸 수 있다. 기능이 구현되어 있어도 진입점이 숨겨져 있으면 존재하지 않는 것과 같다. 목록과 보드를 별도 기능으로 취급하면 폴더 맥락과 방문 기록 복원도 복잡해진다.

### 제품 결정

- 폴더는 하나의 화면이고 `목록 | 보드`는 표현 방식만 바꾼다.
- 폴더를 선택하면 보기 전환을 화면에서 발견할 수 있다.
- 초기 보드는 현재처럼 직접 자식 Markdown 파일만 다룬다.
- 하위 폴더 포함은 실제 사용 수요를 확인한 뒤 별도 옵션으로 만든다.

### 구현 범위

- `TC-04.1` 폴더 화면과 보기 헤더
- `TC-04.2` 목록의 제목·상태·수정 시각·하위 경로
- `TC-04.3` 기존 `FolderKanbanView` 재사용
- `TC-04.4` 보기 전환, 빈 폴더, 속성 미설정 상태 안내
- `TC-04.5` 새 문서, 필터, 정렬 진입점
- `TC-04.6` `TC-01`, `TC-02` 이후 폴더 URL·복원 연결

### 완료 조건

- 컨텍스트 메뉴 없이 보드 보기를 찾고 목록으로 돌아올 수 있다.
- 목록과 보드를 전환해도 같은 폴더 맥락을 유지한다.
- 보드가 직접 자식 문서만 포함한다는 범위를 이해할 수 있다.
- 빈 폴더에서도 새 문서 생성 같은 다음 행동을 선택할 수 있다.

### 위험과 검증

- 폴더 클릭의 확장 동작과 폴더 화면 열기 동작을 명확히 구분한다.
- 큰 폴더에서 목록·보드 렌더링 성능을 측정한다.
- 보기 전환이 불필요한 내부 탭을 추가하지 않아야 한다.

### 관련 구현

- `client/src/features/explorer/Explorer.tsx`
- `client/src/features/database/kanban/FolderKanbanView.tsx`
- `client/src/store.ts`

## TC-05. 문서 속성과 보드 상태 동기화

**상태:** 대기 · **선행:** `TC-03`, `TC-04`; 전체 복원은 `TC-02`

### 분석 이유

문서의 `status`와 보드 카드의 레인은 같은 frontmatter를 표현한다. 두 화면이 각자의 임시 상태와 저장 규칙을 가지면 한쪽의 변경이 늦게 반영되거나 외부 변경과 충돌해 손실될 수 있다.

### 제품 결정

- 문서 속성 변경과 카드 이동은 같은 파일 저장·hash·mtime 충돌 규칙을 사용한다.
- 화면별 진실 공급원을 만들지 않고 디스크와 열린 탭 상태를 일관되게 갱신한다.
- 충돌 시 시작 화면과 관계없이 같은 해결 UI를 사용한다.

### 사용자 흐름

1. 사용자가 보드의 `Doing` 카드를 연다.
2. 문서 속성에서 `status`를 `Done`으로 변경한다.
3. 자동 저장 후 뒤로 가기로 보드에 돌아온다.
4. 같은 카드가 `Done` 레인에 나타나고 이전 필터와 스크롤이 유지된다.

### 구현 범위

- `TC-05.1` 문서 속성 변경 후 보드 쿼리 갱신
- `TC-05.2` 카드 이동 후 열린 문서와 frontmatter 갱신
- `TC-05.3` 외부 변경·동시 저장 충돌 처리
- `TC-05.4` 저장 실패 시 optimistic UI 되돌리기
- `TC-05.5` 대표 사용자 흐름 E2E

### 완료 조건

- 어느 화면에서 상태를 바꿔도 다른 화면에 즉시 반영된다.
- 저장 실패나 외부 변경에서 카드와 문서가 서로 다른 상태로 남지 않는다.
- 보드에서 문서를 편집한 뒤 같은 맥락으로 돌아온다.

### 위험과 검증

- 같은 문서를 여러 브라우저 탭에서 편집하는 경우를 포함한다.
- 드래그 중 파일 변경, rename, 카드 삭제를 테스트한다.
- 보드 레인에 없는 상태 값의 fallback을 정의한다.

### 관련 구현

- `client/src/features/editor/components/FrontmatterPanel.tsx`
- `client/src/features/database/kanban/FolderKanbanView.tsx`
- `client/src/store.ts`
- `server/fs/writeFile.ts`

## TC-06. 작업 재개 중심의 사이드바와 홈

**상태:** 대기

### 분석 이유

현재 Explorer는 검색, 워크스페이스 선택, 열린 문서, 폴더 트리를 한 패널에 둔다. 열린 문서가 늘면 폴더 트리가 줄어든다. 대시보드는 열린 탭 수와 테마처럼 제품 상태를 요약하지만, 재방문 사용자가 다음 행동으로 바로 이어지기 어렵다.

### 제품 결정

사이드바 순서는 워크스페이스 선택기, 검색, 새 노트, 홈·최근·즐겨찾기, 폴더 트리, 접을 수 있는 열린 문서, 설정으로 둔다. 홈은 통계가 아니라 이어 쓰기 화면이다. 내부 열린 문서는 주 탐색이 아닌 보조 전환 수단으로 유지한다.

### 구현 범위

- `TC-06.1` 사이드바 정보 순서와 영역 높이
- `TC-06.2` 마지막 편집 문서와 최근 문서
- `TC-06.3` 최근 작업 폴더와 고정 문서
- `TC-06.4` 빠른 새 노트와 워크스페이스 변경
- `TC-06.5` 열린 문서의 접힘·스크롤·폴더 영역 높이 검증

### 완료 조건

- 경로를 기억하지 않아도 최근 작업을 재개한다.
- 열린 문서가 많아도 폴더 트리를 사용할 수 있다.
- 검색, 새 노트, 최근 작업을 우클릭 없이 찾는다.
- 행동으로 이어지지 않는 통계는 축소하거나 설정으로 이동한다.

### 위험과 검증

- 즐겨찾기와 열린 문서의 중복 밀도를 확인한다.
- 최근 폴더 링크는 `TC-01` URL 모델을 사용한다.
- 내부 탭의 실제 사용 패턴을 관찰한 뒤 기본 펼침 상태를 정한다.

### 측정 지표

- 최근 문서를 다시 여는 시간과 클릭 수
- 열린 문서 20개에서 폴더 탐색 성공률
- 홈 진입 후 첫 유효 행동까지의 시간

### 관련 구현

- `client/src/store.ts`

## TC-07. 반응형·접근성·브라우저 단축키

**상태:** 대기 · **선행:** `TC-03`, `TC-04`, `TC-06`의 주요 레이아웃

### 분석 이유

웹은 전체 화면 데스크톱 창만 사용하지 않는다. Mac 반쪽 창, 작은 노트북, 브라우저 확대에서 고정 폭 모달과 상시 사이드바는 본문을 압박한다. `Cmd/Ctrl+P`, `O`, `N`, `W`는 브라우저의 인쇄, 파일 열기, 새 창, 탭 닫기와 충돌한다. 트리·탭·메뉴는 각각 다른 키보드 규칙을 가지며 색상만으로 상태를 알리면 접근성이 떨어진다.

### 제품 결정

- 넓은 창은 고정 사이드바, 중간 창은 접을 수 있는 사이드바, 좁은 창은 오버레이 서랍형 사이드바를 사용한다.
- 본문은 기본 720~800px 읽기 폭을 검토하고 표·코드·보드는 필요할 때 가로 스크롤을 제공한다.
- 브라우저 기본 단축키와 충돌하는 조합은 보조 경로로만 취급한다.
- 모든 주요 기능에는 화면 진입점이 있으며, 포커스·텍스트·라이브 영역으로 상태를 전달한다.

### 구현 범위

- `TC-07.1` 콘텐츠 기준 breakpoint와 오버레이 사이드바
- `TC-07.2` 모달 `min()` 폭, 본문 읽기 폭, 넓은 콘텐츠 overflow
- `TC-07.3` 충돌 단축키 제거·변경·도움말
- `TC-07.4` 트리·탭·메뉴·popover의 키보드 규칙
- `TC-07.5` `focus-visible`, focus trap, 포커스 복귀
- `TC-07.6` 저장·충돌·연결 오류의 accessible name과 live region
- `TC-07.7` 색상 대비, 200% 확대, `prefers-reduced-motion`

### 완료 조건

- Mac 반쪽 창에서 폴더 탐색, 문서 편집, 속성 수정, 오류 해결을 한다.
- 키보드만으로 폴더 탐색, 문서 열기, 속성 수정, 저장을 끝낸다.
- 포커스가 사라지거나 모달 뒤에 갇히지 않는다.
- 색상을 보지 않아도 저장·충돌·연결 상태를 구분한다.
- 브라우저의 인쇄, 새 탭, 탭 닫기를 예기치 않게 막지 않는다.

### 위험과 검증

- Safari, Chrome, Firefox의 단축키 선점 차이를 확인한다.
- react-arborist와 Radix의 기본 키보드 동작을 중복 구현하지 않는다.
- 자동 저장 알림이 너무 자주 읽히지 않게 한다.

### 관련 구현

- `client/src/App.tsx`
- `client/src/workspace.css`
- `client/src/features/explorer/Explorer.tsx`
- `client/src/shared/components`
- `client/src/shared/design/css/variables.css`

## TC-08. 본문 검색과 자료 비교

**상태:** 대기 · **선행:** `TC-01`, `TC-02`, `TC-07`

### 분석 이유

현재 검색은 파일명과 경로를 빠르게 여는 기능이다. 이는 명령 팔레트로는 좋지만 본문에서 정보를 찾고 여러 결과를 비교하는 검색과는 다르다. 검색이 독립 화면이 아니면 문서를 확인한 뒤 검색어와 결과 위치를 다시 만들어야 한다. PDF, HTML, 이미지 미리보기도 존재하지만 참고 자료와 노트를 함께 보는 흐름으로 연결되지 않았다.

### 제품 결정

- 빠른 파일 열기와 본문 검색을 다른 작업으로 유지한다.
- 본문 검색은 URL, 필터, 결과 위치를 갖는 독립 화면이다.
- 검색 결과는 실제 링크로 제공해 새 탭에서 열 수 있다.
- 나란히 보기는 기본 레이아웃이 아니라 사용자가 요청할 때만 연다.

### 구현 범위

- `TC-08.1` 인덱싱 또는 파일 스캔 전략
- `TC-08.2` 일치 문장과 강조 표시
- `TC-08.3` 폴더·파일 유형·속성 필터와 정렬
- `TC-08.4` 검색 URL과 결과 스크롤 복원
- `TC-08.5` 새 탭 열기와 링크 복사
- `TC-08.6` PDF·HTML·이미지와 문서의 선택형 나란히 보기

### 완료 조건

- 여러 검색 결과를 열어도 검색어, 필터, 위치가 유지된다.
- 파일명 검색과 본문 검색의 차이를 진입점과 화면에서 이해한다.
- 외부 파일 변경 후 검색 결과가 오래된 상태로 남지 않는다.
- 참고 자료를 보며 노트를 편집하고 단일 화면으로 돌아올 수 있다.

### 위험과 검증

- 큰 워크스페이스에서 시작 시간, 메모리, 변경 반영 지연을 측정한다.
- 바이너리, 숨김 파일, `.maek`는 검색 대상에서 제외한다.
- HTML 아티팩트의 격리와 파일 접근 규칙을 유지한다.

### 측정 지표

- 검색 결과 확인 후 같은 검색어를 다시 입력한 횟수
- 첫 결과 표시 시간과 변경 파일 반영 지연
- 여러 자료를 비교하는 작업 완료율

### 관련 구현

- `client/src/features/editor/components/FilePicker.tsx`
- `client/src/store.ts`
- `server/workspace/watch-hub.ts`
- `server/host.ts`

## 실행 순서와 첫 종료 조건

```text
TC-01
  │
  ├→ TC-05 → TC-06 → TC-07 → TC-08
TC-04 ─┘
```

- `TC-01`은 워크스페이스와 문서·폴더 URL을 함께 끝낸다.
- `TC-04`는 독립 구현 뒤 `TC-05`에서 결합한다.
- `TC-07`은 주요 화면 구조가 안정된 뒤 진행한다.

첫 실행 묶음은 `TC-01`부터 `TC-05`까지다. 아래 시나리오가 E2E로 통과하면 종료한다.

1. 주소로 워크스페이스의 폴더 화면을 연다.
2. 목록에서 보드 보기로 전환한다.
3. `Doing` 카드를 같은 탭 또는 새 브라우저 탭에서 연다.
4. 문서의 `status`와 본문을 수정한다.
5. 자동 저장을 기다린다.
6. 같은 탭이었다면 브라우저 뒤로 가기를 누른다.
7. 이전 보드의 필터와 스크롤 위치가 복원되고 카드가 올바른 레인에 표시된다.

## 공통 시각·품질 기준

- 따뜻한 문서 공간, 조밀하고 명료한 탐색, 오래 읽기 좋은 본문을 유지한다.
- 배경 `#F8F7F2`, 문서 표면 `#FFFFFF`, 본문 `#171717`, 보조 텍스트 `#6B7280`, 강조 `#C04E3E`를 출발점으로 사용한다.
- 강조색은 선택, 링크, 주요 작업에 제한하고 성공·경고·오류는 텍스트와 함께 표현한다.
- 기본 간격은 4px 단위로 두고, 모든 요소에 같은 큰 radius와 유리 효과를 적용하지 않는다.
- hover·focus는 80~120ms, 패널 전환은 150~220ms 범위를 검토하며 `prefers-reduced-motion`을 존중한다.
- 한글 UI와 본문은 Pretendard, 코드는 JetBrains Mono를 우선 후보로 두되 외부 CDN보다 로컬 제공을 검토한다.

각 청크는 해당 완료 조건의 E2E 또는 단위 테스트, 라이트·다크 화면 확인, 관련 브라우저 수동 검증을 통과해야 완료로 바꾼다.
