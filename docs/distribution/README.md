# Maek 오픈소스·셀프호스팅 배포 리서치

조사일: 2026-09-17

이 폴더는 Maek를 공개 오픈소스 저장소로 전환하고, 사용자가 자신의 컴퓨터나 서버에서 직접 실행할 수 있게 만들기 위한 사전 조사 문서다. 공식 저장소와 공식 문서를 우선 근거로 사용했다.

## 결론 요약

Maek의 첫 공개 배포는 다음 범위가 가장 적절하다.

1. **GitHub 공개 저장소 + MIT License**
2. **Docker Compose를 대표 설치 방법으로 제공**
3. 컨테이너에는 사용자가 지정한 **단일 workspace만 `/workspace`로 마운트**
4. 기본 포트는 호스트의 `127.0.0.1`에만 공개하고 인증 없는 인터넷 공개는 지원하지 않음
5. `linux/amd64`, `linux/arm64` 이미지를 GHCR에 버전 태그로 게시
6. macOS용 현재 런처는 개발자용 보조 설치로 유지하고, 일반 사용자용 서명 앱은 후속 단계로 분리

네 사례 중 제품·데이터 모델이 가장 가까운 것은 **flatnotes**, 패키징과 로컬/서버 모드 설계는 **SilverBullet**, 릴리스·운영 문서의 완성도는 **Memos**, 데스크톱과 서버를 함께 운영하는 방식 및 AGPL 선택 사례는 **Trilium**이 가장 참고할 만하다.

현재 코드는 아직 컨테이너에 넣기만 해서 배포할 수 있는 상태는 아니다. 서버가 `127.0.0.1`과 로컬 Host 헤더만 허용하고, 클라이언트 URL에도 `localhost` 가정이 있으며, 폴더 선택과 휴지통 기능이 macOS에 의존한다. 또한 `/api/workspaces/open`이 절대 경로를 입력받으므로 비로컬 환경에서는 컨테이너에 마운트한 루트 밖을 절대 열 수 없도록 경계를 추가해야 한다.

## 핵심 의사결정

| 항목 | 권고 | 이유 |
|---|---|---|
| 코드 라이선스 | MIT | 비교 대상 4개 중 3개가 MIT이고, 채택·기여·패키징 장벽이 가장 낮음 |
| 대표 설치 경로 | Docker Compose | 볼륨, 포트, 재시작, 버전 고정을 한 파일로 재현 가능 |
| 데이터 경계 | `/workspace` 단일 bind mount | 임의의 서버 파일 접근을 막고 백업 범위를 명확히 함 |
| 기본 네트워크 | `127.0.0.1:3000` | 현재 인증이 없으므로 로컬 전용이 안전한 기본값 |
| 공개 네트워크 | 첫 릴리스에서는 비지원 | 인증·TLS·proxy 신뢰 경계가 별도 제품 기능으로 필요 |
| 이미지 레지스트리 | GitHub Container Registry | 코드·릴리스·패키지를 한 GitHub 프로젝트에서 관리 가능 |
| 태그 | `vX.Y.Z`를 문서 기본값으로 사용 | `latest` 자동 갱신에 따른 데이터/스키마 위험 회피 |
| 지원 아키텍처 | `linux/amd64`, `linux/arm64` | 일반 서버, Apple Silicon의 Docker, Raspberry Pi 4+ 범위 커버 |

## 공개 전 중단 조건

다음 항목이 확인되지 않으면 라이선스 파일을 추가하거나 저장소를 공개하면 안 된다.

- README에 “Maek Note에서 이식”했다고 적힌 코드와 디자인에 대해 공개 재라이선스 권한이 있는가
- 아이콘, 폰트, 이미지 등 코드가 아닌 자산의 권리자가 누구인가
- 회사·학교·고객 계약에 의해 소유권이 이전된 코드가 섞이지 않았는가
- 외부 코드 복사분과 수정 패치의 원 저작권·고지 의무가 보존되는가
- Git 이력과 추적 파일에 토큰, 개인 경로, 개인 노트 또는 테스트 데이터가 없는가

이 문서는 기술 및 제품 관점의 조사이며 법률 자문은 아니다. 권리관계가 복잡하거나 상업화·투자를 전제로 하면 공개 직전에 변호사 검토가 안전하다.
